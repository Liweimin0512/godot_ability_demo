# RoomLobby 双机 LAN 试玩

联机场景直接实例化主演示的 [RoomLobby](../scenes/room_lobby.tscn)。两名玩家分别控制蓝色和红色角色，按对手的实际位置尝试施放同一个指定目标技能。场景通过独立启动器加载正式 GAS 插件 `4e85c03`，单机主演示可继续从根目录的 `project.godot` 启动。

## 准备和运行

两台机器需要有同版本的 Ability Demo 检出、Git、Python 3.10+、Godot 4.7.2，以及能读取 `4e85c03` 的正式插件 Git 检出。两台机器连入同一局域网。在主机上确认用于 LAN 的 IPv4 地址，并允许同一网络内的 UDP 7000 入站。端口可改，两端须一致。

在主机的 Ability Demo 根目录运行。把示例 IP 换成主机的局域网地址。

```powershell
python tests/run_multiplayer_cast.py --godot "<Godot 可执行文件>" --plugin "<正式插件检出路径>" --lan-host --bind 192.168.1.20 --port 7000
```

主机出现等待提示后，在另一台机器的 Ability Demo 根目录运行。

```powershell
python tests/run_multiplayer_cast.py --godot "<Godot 可执行文件>" --plugin "<正式插件检出路径>" --lan-join 192.168.1.20 --port 7000
```

两端用 WASD 移动，按 Enter 或空格对另一名玩家施法。客户端按 R 断线，再按 R 重连。同一客户端进程会保留重连凭据，关闭窗口会丢失凭据。主机发现断线后保留来宾席位 30 秒，超时后卸载该角色。重启客户端或换另一台机器时，需要等席位过期才能以新的实体 ID 加入。

## 双机验收

| 步骤 | 两端应看到的结果 |
| --- | --- |
| 主机等待，客户端首次加入 | 主机独处时只有蓝色角色。加入后双方看到同样的两个实体 ID，`You` 分别标在各自角色上。 |
| 两端分别移动，再松开 WASD | 两端都看到相同的角色位置。客户端的移动先由主机推进，再经快照返回。角色被限制在大厅的可走地面范围内。 |
| 出生点直接施法，再走近至 5 米内施法 | 出生点相距 11 米，收到 `TARGET_INVALID`，Mana 仍为 10。进入范围后施法显示前摇，成功时施法者 Mana 从 10 到 6、开始冷却，对手出现黄色标记。 |
| 前摇中把目标移出 5 米 | 提交返回 `TARGET_INVALID`，费用、冷却和标记无写入。可调整两人起始距离，让目标站在范围边沿，等前摇出现后向外移动。 |
| 停下移动，由客户端施法。前摇中按 R，看到主机移除来宾后再按 R | 主机取消未提交施法。重连后实体 ID 和离开时的位置一致，Mana、冷却和标记保持结算前的状态。 |
| 重新施法，结算后客户端再按 R 重连 | 30 秒内重连会恢复同一角色。已扣费用保留，冷却与标记继续按主机时间推进。若重连发生在到期之后，看到的是已到期的快照。 |
| 客户端断线并等待席位过期 | 主机保持可移动，来宾从场上消失。再次加入时出现新实体 ID、出生位置和 10 点 Mana。 |

开始需要满 Mana 的用例前，可以关闭并重开双方进程。运行器支持本机双进程冒烟，用同一场景覆盖初始超距拒绝、移动入范围、前摇中移出范围、前摇及提交后重连、写入次数和到期。

```powershell
python tests/run_multiplayer_cast.py --godot "<Godot 可执行文件>" --plugin "<正式插件检出路径>" --lan-smoke
```

去掉 `--lan-smoke` 可复跑原有九组回归。 [演示测试说明](../tests/README.md)

## 宿主边界

`lan_match.gd` 管理连接、每次重连的新会话、角色保留及卸载、实体 ID 和移动输入。客户端只提交方向与施法意图，主机按速度和大厅边界推进位置，目标距离在受理和前摇提交时分别用主机坐标判断。角色位置和标记的展示由 `lan_view.gd` 消费快照。当前移动使用地面边界约束，出生和重连仅在同一个 RoomLobby 场景。席位凭据适用于可信 LAN 内同一客户端进程的重连；跨互联网认证、加密、跨场景移动和完整碰撞仍由实际宿主接入。
